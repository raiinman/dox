# Working on DOX

Read [the portable contract](starter/AGENTS.md) and [START-HERE.md](START-HERE.md) before editing. The contract applies to this repository too; these are additional local rules.

## Purpose and ownership

DOX helps someone return to a project without reconstructing chat history. Prioritize a trustworthy answer to: where did we stop, and what happens next?

- `README.md`: introduction and adoption.
- `START-HERE.md`: current state of this redesign, maintained by the working agent.
- `starter/AGENTS.md`: reusable workflow and instructions for the four-file portable kit. No additional child contract is needed.
- `guides/`: migration, fictional example and design decisions, owned by this root contract.
- Existing images, `LICENSE` and `COPYRIGHT.md`: preserve files and attribution. Artwork is presentation, not authority.

## Work guidance

- Keep resume summaries to roughly 150 words or fewer, with evidence below.
- Preserve paths, evidence, ownership, uncertainty and constraints when shortening.
- Keep one authoritative state page per project; map an existing equivalent first.
- Do not create instruction hierarchies merely because folders exist.
- No personal chat exports, private project paths or health information in this public framework.
- This is Markdown. Do not imply background capture, synchronization, clinical effectiveness or guaranteed agent adherence.
- Workflow changes must update the starter and relevant adoption/example docs together.

## Verification

Check local Markdown links, anchors, the four-file starter inventory and upstream attribution. Walk interrupted work, failed checks, stale state and existing-project migration using `guides/EXAMPLE.md`. Report what was actually checked. There is no application build or unit-test suite.
